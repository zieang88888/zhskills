# 选题日历 · xiaohongshu-topic-planner

> **二次开发**：本技能改编自 [《小红书运营手册 · AI工作台》](https://xiaobot.net/p/xiaohongshuku) 的选题策划 / topic-planner（MIT © 2026 王梦珂），在保留其核心方法论基础上，升级为「提示词 + 可执行 CLI」双形态。署名见本目录 `NOTICE.md` 与仓库 `THIRD_PARTY_NOTICES.md`。

## 这个技能做什么

把"账号定位 + 运营目标"拆成一套**可连续执行的选题系统**，而不是泛泛列题：

- 每条选题必须回答一个问题——**发这条是为了什么**（功能标签）；
- 6 类功能选题各有定义与配比，账号所处阶段不同，配比不同；
- 发布日历按**功能节奏**排布，相邻两天不发同质化选题；
- 若账号已有定刊（与 xiaohongshu-magazine 联动），每条选题挂回对应的栏目 / 母题。

与 xiaohongshu-magazine 的关系：**magazine 定"方向"（母题与栏目），本技能排"日历"（在既定栏目下把选题落到日期）**。一个管战略，一个管战术。

典型场景：

- 小红书 / 公众号 / 知乎账号的月度选题规划与内容排期；
- 新账号冷启动：先吸引、共鸣，快速建立"这和我有关"；
- 稳定期账号：往信任、转化倾斜，让内容真正支撑业务目标；
- 系列内容策划：把一个大主题拆成连续更新的小专题。

## 输入要求

- **必填**：
  1. **账号定位**：这个账号是谁、面向谁、提供什么价值（行业 / 领域一句话说清）；
  2. **运营目标**：这一周期最想达成什么——涨粉 / 冷启动 / 建立信任 / 新品发布 / 转化变现 / 互动评论。
- **可选**：
  3. 规划周期天数（默认 14 天；CLI 中用 `--days` 注入）；
  4. 已有栏目 / 母题（来自 magazine 定刊成果，用于把选题挂回栏目）；
  5. 近期热点、产品 / 服务信息、价格区间、交付方式；
  6. 已发过的内容或口述想法（避免重复）。
- 信息不足时：先用用户已给信息产出可执行版本，缺的部分标注"（待确认）"；**不编造行业数据、平台趋势或爆款承诺**。

## 输出结构（模板见 scripts/templates/xiaohongshu-topic-planner.template.md）

一份完整选题日历，自上而下 5 节：

1. **账号定位与目标复述**：一段话复述账号是谁、面向谁、本周期目标是什么；信息不足处标"（待确认）"。
2. **选题池**：按 6 类功能分组（吸引 / 共鸣 / 信任 / 教育 / 转化 / 互动），每条四要素：标题方向、功能标签（发这条是为了什么）、一句话思路、对应栏目（有定刊成果则挂回，否则写"（待挂栏目）"）。
3. **优先级排序**：按"对目标达成的贡献"排序，前 5 条必须各给一句理由（为什么先做这条、它如何支撑本周期目标）。
4. **发布日历**：表格——日期 / 选题 / 功能 / 栏目 / 发布形式（图文 / 视频 / 清单 / 案例等）。排布遵循功能节奏：相邻两天不连续排同一功能，吸引与信任、教育与转化交替出现，避免同质化。
5. **系列选题建议**：列出 1-3 个可拆成连续系列的主题，每个系列给出更新顺序（先讲什么、后讲什么）。

## 工作流程

1. **复述定位与目标**：先用一段话回读账号定位与本周期目标，让用户确认理解没错；缺信息标"（待确认）"。
2. **判断账号阶段、定 6 类配比**：冷启动期重吸引 + 共鸣（让目标用户觉得"这说的就是我"）；稳定期重信任 + 转化（让老粉知道你能解决什么、适合谁）；教育、互动贯穿全程做调节。
3. **出选题池**：按 6 类各出若干条，每条强制带功能标签与一句话思路；有定刊成果的挂回栏目。
4. **排优先级**：按目标贡献排序，前 5 条写清理由。
5. **排发布日历**：按功能节奏把选题落到具体日期，相邻不同质化。
6. **挖系列**：从选题池里挑可连续追更的主题，给出更新顺序。

## 质量规则（必须遵守）

- **每条选题必须带功能标签**，且必须与本周期目标相关——不服务于任何目标的选题不要写进日历。
- **日历不连续排同一功能**：相邻两天不得是同一类功能选题（如连续两天都发"吸引"）。
- **不编造数据、不承诺爆款**：不引用外部行业数据、他人案例或"必火""涨粉多少"之类的承诺。
- **与 magazine 的联动必须写明**：有栏目 / 母题时，每条选题标注对应栏目；没有时在选题池中标"（待挂栏目）"，并在末尾提示用户先跑 magazine 定刊。
- **信息不足标"（待确认）"**，不替用户脑补定位或目标。
- **功能标签用"发这条是为了什么"的句式**，而不是空泛的"干货""分享"。

## 边界与异常处理

- 用户只给了定位、没给目标 → 默认按"冷启动涨粉"排期，并在定位复述节标注"目标（待确认）"。
- 用户既无定位也无目标 → 先输出带"（待确认）"占位的日历骨架，并提示至少补齐"面向谁 + 想达成什么"。
- 周期天数过大（如 30 天以上）→ 选题池可分主题批出，但日历仍按功能节奏排布，不堆同质化选题。
- 用户要求"照抄某个竞品的爆款" → 不代抄、不承诺复刻，只按功能方法论给同功能位的替代选题。
- 跨平台（小红书 / 公众号 / 知乎）→ 选题功能分类通用，发布形式一栏按平台习惯标注。

## 与脚本配合

- 批量 / 命令行场景：`scripts/draft_xiaohongshu_topic_planner.py`（纯标准库，一条命令跑通）；输入为账号定位与运营目标的文本（可附已有栏目、热点、素材），输出为成稿选题日历 Markdown；`--days` 控制规划天数（默认 14）。
- 自定义模板：复制 `scripts/templates/xiaohongshu-topic-planner.template.md` 修改后使用。
