# 合同审查 · contract-guard

> **二次开发**：本技能改编自 [he-yufeng/ContractGuard](https://github.com/he-yufeng/ContractGuard) 的合同审查 AI Agent（MIT © 2026 Yufeng He），在保留其核心方法论基础上，升级为「提示词 + 可执行 CLI」双形态。署名见本目录 `NOTICE.md` 与仓库 `THIRD_PARTY_NOTICES.md`。

## 这个技能做什么

把一份合同文本（或条款摘要）按**审查方立场**做结构化审查，输出一份可直接用于谈判决策的 Markdown 审查报告。

核心方法论（四件套）：

1. **条款四分类**：把合同里每一条有实质影响的条款归入四类——
   - 🔴 **红旗（Red Flags）**：对我方明显不利、或涉嫌违反强制性规定、签了可能造成财务损失 / 法律责任 / 权利丧失的条款，签署前必须顶回去；
   - 🟡 **警告（Warnings）**：中等风险、值得谈但不一定是 deal-breaker 的条款，常见于很多合同但仍需知晓；
   - 🟢 **保护（Protections）**：对我方有利的条款，合同写对了的地方，谈判时不要被对方改掉；
   - ⚪ **缺失保护（Missing Protections）**：按行业惯例应当有、但合同里没出现的标准保护条款，缺位可能让我方暴露风险。
2. **公平评分**：对合同整体及关键条款给 A+（对双方都公平、优秀）到 F（严重一边倒、红旗遍地）的等级，附一句话理由。评分依据是红旗/警告的数量与严重程度，以及现有保护条款的平衡度。
3. **中国法强制规定对照**：把中国法常见强制性规定作为固定检查清单，逐项核对合同原文——试用期长度与工资下限、竞业限制范围与补偿、加班费 150%/200%/300% 下限、定金比例上限、民间借贷利率不超过签约时一年期 LPR 4 倍、禁止预扣利息、保密义务合理性等。每项给出"规定内容 / 原文对应 / 合规与否"，原文没写就如实标"未约定（待确认）"，不冒充合规。
4. **修改建议**：对每一条红旗/警告给出具体修改方向，写成可直接拿去谈判的表述，而不是只说"这条不好"。

典型场景：合同签署前自查、采购合同审查、销售合同审查、劳动合同审查、合作协议/框架协议审查、条款谈判前的准备工作。

## 输入要求

- **必填**：合同正文（全文，或至少是含关键条款的摘要）。支持纯文本 / Markdown 粘贴，或 CLI 传入文件路径。
- **必填（CLI 参数）**：`--side` 指明审查立场——我方是**甲方**（付款方 / 委托方 / 出租方 / 用人单位等强势或主动方）、**乙方**（收款方 / 承揽方 / 承租方 / 劳动者等相对弱势方）、还是**中立**（无立场、只做客观公平性评估）。默认乙方。立场决定"红旗/保护"的判断方向。
- **可选**：合同类型（采购 / 销售 / 劳动 / 租赁 / NDA / 借款 / 合作等），不给则由模型自动识别；交易背景简述（金额、期限、谈判地位）。
- 信息不足时：不脑补未出现的条款；确实需要背景才能判断的地方标"（待确认）"，并在报告末尾统一列出。

## 输出结构（模板见 `scripts/templates/contract-guard.template.md`）

一份完整审查报告，自上而下 6 节：

1. **合同概要**：合同名称 / 性质（类型）/ 审查立场（我方甲方/乙方/中立）/ 一句话总览。
2. **条款分类清单**：四张表（红旗 / 警告 / 保护 / 缺失保护），每条含：条款编号或位置、原文摘录（忠于原文）、风险或价值说明、影响方向。四表每类都必须出现——没有就写"无"。
3. **公平评分**：整体等级（A+ ~ F）+ 一句话理由；关键条款单独评分并附理由。
4. **强制规定对照**：逐项列出中国法常见强制规定（试用期 / 竞业限制 / 加班费 / 定金 / LPR 4 倍利率 / 禁止预扣利息 / 保密义务等），每项三栏：规定内容 / 合同原文对应 / 合规与否（合规 / 违规 / 未约定-待确认）。
5. **修改建议**：按优先级（高→低）排序，每条针对一个红旗/警告条款，给出可直接用的修改表述方向（不是泛泛而谈）。
6. **待确认与边界声明**：信息不足处汇总（待确认）；明确声明——本报告不构成法律意见，法规以最新有效版本为准，重大决策请咨询执业律师。

## 工作流程

1. **读合同、定立场**：通读全文，识别合同类型与交易结构；按 `--side` 确定判断视角（甲方/乙方/中立）。
2. **逐条分类**：把每条有实质影响的条款归入红旗 / 警告 / 保护 / 缺失保护四类；忠于原文，原文没有的绝不脑补成"缺失"。
3. **打分**：根据红旗与警告的数量、严重程度，对照保护条款的平衡度，给出整体 A+~F 等级与一句话理由；对关键条款单独打分。
4. **过强制规定清单**：拿中国法固定检查项逐条比对原文——找到对应条款就判断合规性，找不到就标"未约定（待确认）"，不许漏项。
5. **出修改建议**：对每条红旗/警告写具体修改方向，能给出可直接粘贴的替换表述最好。
6. **收尾**：汇总待确认项，加边界声明，按模板输出。

## 质量规则（必须遵守）

- **忠于原文**：只审查合同里真实出现的条款；原文没有的事实（金额、日期、主体）不得编造；分类引用必须摘录原文。
- **四分类每类必须出现条目**：某一类确实没有，就写"无"，不许省略整张表。
- **强制规定逐项核对不遗漏**：试用期、竞业限制、加班费、定金、LPR 4 倍利率、禁止预扣利息、保密义务等固定检查项每一项都要在对照表中出现；原文未涉及就如实标"未约定（待确认）"，不得默认通过。
- **立场一致**：所有红旗/保护判断必须与 `--side` 选定的立场一致——同一条款对甲方是保护、对乙方可能是红旗，不许前后矛盾。
- **修改建议可落地**：不只说"这条不公平"，要写"建议改为……"，给出谈判可直接用的方向。
- **不确定标（待确认）**：合同信息不足以判断时，明确标注并列入末尾待确认清单。
- **法规效力边界必须声明**：报告末尾必须出现"本审查不构成法律意见、法规以最新有效版本为准"。

## 边界与异常处理

- 合同极长（超过单次上下文）→ CLI 自动按段切分，逐段审查后合并；合并处用"## 补充内容（第 N 段）"标注。
- 合同类型无法识别 → 按通用民商事合同审查，并在概要中标"类型待确认"。
- 立场未指定 → 默认按乙方（相对弱势方）审查，这也是大多数个人用户 / 供应商 / 劳动者的真实处境。
- 涉外合同 / 适用境外法律 → 中国法强制规定对照表标注"不适用（待确认适用法律）"，不硬套中国法。
- 扫描件 / 图片 PDF → 本 CLI 只接纯文本；提示用户先做 OCR 提取文本。
- 审查结论与用户直觉冲突 → 以原文和强制规定清单为准，不因为用户"觉得没问题"就降级红旗。
