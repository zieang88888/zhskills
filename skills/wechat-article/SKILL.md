# 公众号长文流水线 · wechat-article

> **二次开发**：本技能改编自 [wewrite](https://github.com/oaker-io/wewrite) 的 skills/wewrite/SKILL.md（MIT © 2026 OpenClaw），在保留其分阶段写作与编辑审稿方法论基础上，去除原项目对 wewrite CLI 命令与任务目录结构的依赖，升级为「提示词 + 可执行 CLI」双形态。署名见本目录 `NOTICE.md` 与仓库 `THIRD_PARTY_NOTICES.md`。

## 这个技能做什么

把一个公众号写作任务（选题、目标读者、账号定位、已有素材），按固定的分阶段校验流程，产出一份可交付的长文文档：

1. **brief / claims**：先不写稿，把写作任务与意图拆成一份「核心主张清单」——这篇文章到底要让读者记住哪几个判断，每个主张有没有依据。
2. **draft**：基于主张清单写初稿。初稿不是成稿。
3. **review_report**：以编辑视角按五项标准审稿——事实、观点、实用性、账号声音、可读性；只有编辑结论为 pass，才进入定稿。
4. **封存**：正文定稿后不得随意改写；要改就回到对应阶段重跑并重新审稿。

本技能**只产出正文与审稿报告**：不发布到草稿箱、不配图、不做排版。

## 输入要求

- **必填**：写作任务说明——选题 / 主题、想让读者看完记住什么、目标读者是谁。
- **强烈建议提供**：账号定位与口吻、已有素材（数据、案例、原话、来源）、篇幅预期。
- **事实依据**：zhskills 无联网搜索权限。凡是事实性陈述（数字、引述、案例、时间、人名、机构名），必须来自用户提供的素材；用户没给依据的，一律标注「（待核实）」，不得用模型记忆补成"已核实事实"。
- CLI 调用时输入为一个文本文件（或 `-` 读 stdin），把上述信息写进去即可。

## 输出结构（模板见 scripts/templates/wechat-article.template.md）

单次运行 `all` 阶段产出一份四段式文档：

1. **核心主张清单（Claims）**：每条主张一句话，附依据来源；无依据的标「（待核实）」。
2. **文章初稿（Draft）**：标题 + 正文 Markdown。
3. **自审报告（Review）**：按事实 / 观点 / 实用性 / 账号声音 / 可读性五项逐条给结论与修改意见。
4. **定稿建议**：编辑结论（pass / need_revision）、待核实事项清单、封存纪律提醒。

## 工作流程

1. **brief**：重读用户任务，明确读者、目的、账号声音；把模糊选题收敛成 3–7 条可被验证的核心主张。
2. **claims**：逐条标注依据——用户素材 / 公开常识 / （待核实）。依据不足的主张要么删掉，要么降级为观点。
3. **draft**：围绕主张写初稿；事实只引用清单里的主张，不临时新增未经核实的数字。
4. **review**：用编辑眼光重审初稿：
   - **事实**：每个数字、引述、案例都能在主张清单里找到依据吗？
   - **观点**：判断是否鲜明、前后一致，有没有骑墙和空话？
   - **实用性**：读者看完能拿走什么（方法 / 判断 / 情绪）？
   - **账号声音**：像这个账号写的吗？口吻统一吗？
   - **可读性**：长句、堆砌、跳转、小标题节奏、开头 3 行能不能留住人？

   发现可修问题直接给修改意见；只有五项都过（pass）才建议定稿。
5. **封存**：定稿后不再回改字句；后续配图、排版、发布由用户另行决定，本技能不代劳。

## 质量规则（必须遵守）

- **不伪造事实**：搜索 / 外部依据缺失时，可以写分析和经验判断，但**不得把模型记忆包装成已核实事实**；任何无来源的事实性陈述必须带「（待核实）」。
- **主张先行**：没有核心主张清单之前不写初稿；初稿里的事实不得超出清单依据。
- **审稿是硬门槛**：五项标准逐条过，编辑结论不是 pass 就必须在报告里写明待修项，不得"假装通过"。
- **封存纪律**：定稿后正文不得随意改写；修改必须回到对应阶段并重审。
- **发布需授权**：本技能绝不自动发布；推送到公众号草稿箱或正式发布必须由用户明确授权，且不属于本技能职责。
- **只写正文**：不生成配图提示词、不做排版样式、不生成封面。

## 边界与异常处理

- 用户没给素材又要求事实 → 正常写，但所有事实性陈述标「（待核实）」，并在自审报告里集中列出。
- 选题过大 → 收敛到一个读者、一个判断、一条主线；收敛不下来就在报告里说明。
- 输入过短、意图不清 → 先输出主张清单，并在开头标注「依据不足，建议补充素材后再写初稿」。
- `--stage review` 单独使用时，输入应为待审文章全文。
- 接口报错 / 无 Key / 网络不通 → 脚本中文报错退出，不产出半成品。

## 与脚本配合

- 命令行场景：`scripts/draft_wechat_article.py`（纯标准库，一条命令跑通四阶段）。
- `--stage all`（默认）一次产出四段式文档；`--stage brief` 只出主张清单；`--stage draft` 只出初稿；`--stage review` 对传入的初稿做五项审稿。
- 自定义模板：复制 `scripts/templates/wechat-article.template.md` 修改后使用。
