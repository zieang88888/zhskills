# 信息可信度核查 · analyze-claims

> **二次开发**：本技能改编自 [danielmiessler/fabric](https://github.com/danielmiessler/fabric) 的 analyze_claims（MIT License © 2012-2024 Scott Chacon and others），在保留其核心方法论基础上，升级为「提示词 + 可执行 CLI」双形态。署名见本目录 `NOTICE.md` 与仓库 `THIRD_PARTY_NOTICES.md`。

## 这个技能做什么

把一段含论断的文字（新闻、群聊消息、营销文案、汇报材料、文章节选）拆成**一条可单独检验的声明**，逐条回答四个问题：这句话在主张什么？它可证伪吗？文中给出的证据是什么、来源可靠吗？它与已知事实冲突吗？最后给出每条声明的可信度结论和一张"建议去查什么"的清单。

核心方法论（改编自 fabric analyze_claims）：

- 先把"整段话"与"它要论证的主张"在脑子里分开，再把主张拆成可逐条检验的声明；
- 区分**断言的事实**与**作者的观点**——事实断言走证据评估，价值判断 / 情绪表达不冒充事实；
- 每条声明都要给证据强度、来源可靠度与一个明确的可信度评级，评级只看证据、不看立场；
- 不编造证据：拿不出外部可验证的证据就如实写"无据"并说明理由，而不是替原文补一个来源。

典型场景：新闻 / 消息甄别、营销文案把关、汇报材料事前核查、谣言辨析、合同 / 政策解读材料可信度初筛。

## 输入要求

- **必填**：待核查文本——一条或多条声明均可，整段粘贴即可；建议同时提供其来源出处（公众号 / 媒体 / 群聊 / 汇报材料）与发布时间，用于判断来源可靠度与时效性。
- **可选**：用户已掌握的背景事实、对某条声明的预设立场（核查时反而要警惕立场影响）、希望重点核查的条目。
- 信息不足时：来源未注明就标"来源可靠度：未注明"，不得替原文脑补出处；拿不准的声明标注（待核实），不要硬下结论。

## 输出结构（模板见 `scripts/templates/analyze-claims.template.md`）

一份 Markdown 核查报告，自上而下：

1. **标题与概览**：`# 信息可信度核查 · {核查对象一句话}`，注明核查范围与声明条数。
2. **声明拆解**：表格逐条列出——编号 / 原文片段 / 类型（事实断言 / 价值判断 / 情绪表达 / 建议）/ 可证伪性（可通过事实验证 / 不可证伪）。原文出现的每条声明都要进表，不遗漏。
3. **逐条评估**：表格逐条列出——编号 / 证据强度（有据 / 部分有据 / 无据）/ 来源可靠度 / 与已知事实是否冲突 / 说明（判"无据"必须写明理由）。
4. **可信度结论**：表格逐条列出——编号 / 可信度（高 / 中 / 低）/ 一句话理由。
5. **需核实清单**：哪些断言建议实际查证、具体查什么（数据出处、原始来源、发布时间、统计口径）。
6. **边界说明**：本报告仅基于文本分析，不替代查证；模型知识可能过时，时效性数据以权威来源为准。

## 工作流程

1. **通读并拆分**：把整段话通读一遍，拆成一条条可单独检验的声明；一句话里含多个断言时拆开（如"该产品销量增长 30%，远超竞品"要拆成"销量增长 30%"与"远超竞品"两条）。
2. **逐条定性**：为每条标类型与可证伪性；把价值判断、情绪表达从事实断言里分离出来。
3. **逐条评估证据**：对每条问——文中给证据了吗？证据来源是什么、可靠吗？与公认常识 / 已知事实冲突吗？据此给证据强度与来源可靠度。
4. **下结论**：每条给高 / 中 / 低可信度与一句话理由；只按证据，不因立场翻转结论。
5. **列需核实清单与边界**：把无法仅凭文本判断、必须外部查证的条目汇总成清单，写清查什么；末尾写明本报告的边界。

## 质量规则（必须遵守）

- **声明拆解不遗漏**：原文出现的每条断言、判断、情绪、建议都要进表；一句话多断言时必须拆开，不得合并跳过。
- **"无据"必须有理由**：证据强度判"无据"时，说明具体理由（如"仅为作者主观判断""文中未给出任何数据或来源""无法外部验证"），不允许只写"无据"两个字。
- **不因立场给结论**：只按证据强度、来源可靠度、与已知事实是否冲突来评级；不因为声明符合或违背用户立场就调高 / 调低可信度。
- **不确定标（待核实）**：信息不足、来源不明或超出模型知识范围时，标注（待核实），不硬下"高 / 低"结论。
- **不编造证据与来源**：证据只能来自原文或公认常识；不得虚构数据、统计口径、引用链接或外部来源。
- **区分事实与观点**：价值判断与情绪表达如实标注类型，不得按事实断言的标准要求其"提供证据"，也不得把观点包装成事实。

## 边界与异常处理

- 文本**全是情绪表达 / 口号**（无可检验事实断言）→ 如实说明该文本以情绪动员为主、无可证伪事实，可信度结论相应给出，并提示此类内容不承载可核查事实。
- 涉及**时效性强的数据**（股价、疫情、事故伤亡、最新政策）→ 一律标注（待核实），并在需核实清单里写明以发布当日权威来源为准；模型知识可能过时。
- 声明**超出模型知识范围**（小众事件、内部数据）→ 不硬评，标（待核实），给出建议查证渠道。
- 原文**来源未注明** → 来源可靠度标"未注明"，并在需核实清单中提示先查出处再采信。
- **中英混杂**（涉外新闻、英文报告节选）→ 专有名词保留原文，报告正文用中文。

## 与脚本配合

- 批量 / 命令行场景：`scripts/draft_analyze_claims.py`（纯标准库，一条命令跑通）；输入为待核查声明文本（可附来源与上下文），输出为成稿核查报告 Markdown。
- 自定义模板：复制 `scripts/templates/analyze-claims.template.md` 修改后使用。
