# 评论区回复 · xiaohongshu-comment-reply

> **二次开发**：本技能改编自 [xiaohongshu-ai-workbench](https://github.com/mengke-wang/xiaohongshu-ai-workbench) 的 xiaohongshu-comment-reply（MIT © 2026 王梦珂），在保留其"真人感回复"方法论基础上，升级为「提示词 + 可执行 CLI」双形态，并把场景从小红书泛化到中文互联网评论区（客服话术、差评回复、社群互动、微博评论区）。署名见本目录 `NOTICE.md` 与仓库 `THIRD_PARTY_NOTICES.md`。

## 这个技能做什么

把用户丢来的一条或多条评论（或一段需要配置顶评论的笔记正文），变成**像真人会说、有边界、能延续对话**的回复草稿，而不是客服模板腔。核心是"先接住对方，再表达自己"：

- **单条评论**：给 4 个可直接用的版本（友好 / 专业 / 更像评论区 / 引导私信）+ 1 个"不建议这样回"反例及原因。
- **多条评论**：逐条给推荐回复与备选回复，末尾给一条置顶评论建议。
- **恶意 / 高风险评论**：不争辩，优先给"不回复 / 置顶统一说明 / 举报 / 删除"的处理建议。

## 输入要求

- **必填**：评论内容（一条原文，或多条评论的列表）；或笔记 / 帖子正文（要求生成置顶评论时）。
- **可选**：账号人设 `--persona`（专业 / 亲切 / 幽默 / 品牌号 / 个人 IP）——决定语气重心；不提供时默认温和、清楚、不硬推。
- **可选**：场景（小红书 / 微博 / 社群 / 电商客服差评）、笔记主题、不能说的话与合规边界。
- 信息不足时可合理推断语气与场景，但**禁止编造产品事实、价格、优惠、效果、身份与背书**。

## 输出结构（模板见 `scripts/templates/xiaohongshu-comment-reply.template.md`）

单条评论固定 5 段：

1. **友好回复**：先回应对方说了什么，语气轻松，能聊下去。
2. **专业回复**：信息准确、有边界，适合品牌号 / 知识型账号。
3. **更像评论区的回复**：短、像真人接话，可带一点口语节奏。
4. **引导私信版**：仅当对方确实需要一对一沟通时才给；不需要时明确写"本条不建议引导私信"。
5. **不建议这样回**：一个危险 / 生硬 / 抬杠 / 过度承诺的写法 + 原因。

多条评论：每条「原评论 / 推荐回复 / 备选回复」，末尾给置顶评论建议；置顶评论请求给 A 补充价值 / B 引导讨论 / C 引导体验三条。

## 工作流程

1. **先读对方**：这条评论是夸、是问、是质疑、是抬杠、还是真有需求？判断情绪和意图。
2. **承接**：开头先回应对方说的内容（复述关键词、认可顾虑、接住情绪），再补自己的意思。
3. **按人设调语气**：专业给信息与边界；亲切给温度；幽默可以接梗但不刻薄；品牌号稳重克制；个人 IP 像朋友说话。
4. **出 4 + 1**：四个版本各有分工，反例写出"哪种写法会出事"。
5. **敏感词自查**：价格、效果、法律、医疗、财务相关内容，不做承诺、不下定论、不替用户打包票。
6. **恶意评论降级**：不陪着吵，给处理建议。

## 质量规则（必须遵守）

- **先回应再补充**：每条回复的前半段必须接住对方原话，不许自说自话。
- **少客服腔**：默认不用"亲""呢""哦～""感谢您的反馈呢"这类模板句；感叹号默认不用，最多 1 个。
- **不吵架不阴阳**：不抬杠、不反讽、不翻旧账、不在公开评论区和人对线。
- **不硬导私信**：不是每条都往私信引；对方没这个需求时不要推送。
- **质疑类先承接**：先承认对方关心点 / 顾虑合理，再说明边界，不许一上来就辩解。
- **敏感领域不承诺**：价格、效果、法律、医疗、财务相关，用"以官方页面 / 合同 / 医生意见为准""具体情况具体看"，不写死。
- **不编造事实**：产品参数、优惠、发货时间、资质背书，输入没给就不写；不知道就写"（待确认）"。
- **恶意评论不争辩**：优先建议不予回复 / 置顶统一说明 / 举报 / 删除，不帮着写骂回去的话。

## 边界与异常处理

- 评论信息太少（只有一个表情或"沙发"）→ 给一句轻松接话即可，不硬凑四个版本。
- 评论涉及人身攻击、辱骂、引战 → 不生成对线回复，直接给处理建议。
- 评论涉及医疗诊断、法律纠纷、投资建议 → 只引导咨询专业人士 / 官方渠道，不输出专业结论。
- 对方在问具体购买 / 售后 → 引导私信或官方客服渠道时写清"具体细节私信聊"，不在公开区报价。
- 多条评论时逐条独立处理，最后置顶评论要能覆盖评论区最高频的问题。

## 与脚本配合

- 批量 / 命令行场景：`scripts/draft_xiaohongshu_comment_reply.py`（纯标准库，一条命令跑通），人设用 `--persona` 指定。
- 自定义模板：复制 `scripts/templates/xiaohongshu-comment-reply.template.md` 修改后使用。
