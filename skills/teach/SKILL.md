# 培训教案 · teach

> **二次开发**：本技能改编自 [mattpocock/skills](https://github.com/mattpocock/skills) 的 teach（MIT © 2026 Matt Pocock），在保留其核心教学法基础上，裁剪为单轮 Markdown 教案交付。署名见本目录 `NOTICE.md` 与仓库 `THIRD_PARTY_NOTICES.md`。

## 这个技能做什么

把一个培训主题，设计成一份**可直接执行的教案大纲**：从教学目标出发，贴着学员现有水平排内容，并用学习科学方法把练习做实。不做多会话 HTML 教学环境、不做逐课对话式教学——一次输出完整教案 Markdown，拿过去就能开讲。

保留的教学法内核（源自原 teach 技能）：

- **MISSION 驱动**：先想清楚学员为什么学、学完要能做什么，所有内容围绕这个目标取舍；目标不清，后面排的内容就会发飘；
- **最近发展区（Zone of Proximal Development）**：内容难度贴着学员现有水平、只略高一点点；学员已经会的一笔带过，也不直接跳到远超水平的内容；
- **三种学习科学方法显式落地**：提取练习（retrieval practice，从脑子里往外捞，而非反复看）、间隔重复（spacing，把练习摊到时间上）、交错练习（interleaving，混合相关但不同的题型）——追求长期留存（storage strength），而不是课堂上一时眼熟（fluency）带来的掌握错觉；
- **评估与反馈闭环**：每个目标都有可检验的课后检验方式；每个练习都要写清楚怎么给学员反馈、反馈要快。

典型适用场景：

- **新人入职培训**：岗位流程、工具、合规红线的第一堂课；
- **带教 SOP**：老带新、师徒制的带教计划；
- **产品 / 合规 / 销售培训**：面向客户或面向内部的专项培训；
- **技能内训**：软技能、硬技能的部门内训课程设计。

## 输入要求

- **必填**：
  1. **培训主题**：这堂课教什么（如"新客服的退款流程处理"）；
  2. **学员背景**：学员现在会什么、什么岗位、大致水平（如"刚入职 3 天的客服，会用工单系统但没处理过退款"）。
- **可选**：总时长（分钟，CLI 用 `--duration` 传入）、人数、培训形式（线下/线上/混合）、必须覆盖的知识点或红线。
- 信息不足时：学员背景里不清楚的水平与缺口，在教案里标注"（待确认）"，**不脑补**；必要时提示主讲人课前做一次前置摸底。

## 输出结构（模板见 `scripts/templates/teach.template.md`）

一份完整教案，自上而下六节：

1. **教学目标（MISSION）**：2–4 条**可检验**的目标，每条用行为动词开头（能说出 / 能操作 / 能判断 / 能独立完成……），写完要能回答"学员课后具体会做什么"；
2. **学员画像与前置评估**：现有水平、知识缺口、最近发展区判断；信息不足处标"（待确认）"；
3. **课程大纲**：分模块，每个模块列——内容要点 / 教学动作（讲、演示、带练、讨论）/ 时长（分钟）；各模块时长之和必须等于总时长；
4. **练习设计**：三种学习科学方法**各至少 1 个具体练习**——提取练习（给具体回忆题，不是"大家回忆一下"）、间隔重复（给出一张跨天/跨周的复习安排表）、交错练习（混合不同题型/不同情境的混练）；
5. **评估方式**：课后怎么检验教学目标真的达成了（笔试 / 实操 / 情景模拟 / 作业 + 及格线）；
6. **课后巩固**：间隔复习计划（哪天复习哪块）+ 本主题学员最常犯的 3–5 个错误及纠正提示。

## 工作流程

1. **定 MISSION**：先写下学员学完这堂课后"会做什么"——把模糊的主题（如"教会用我们的 CRM"）改成可检验的目标（如"能独立在 CRM 里走完一次从建客户到出单的全流程"）；
2. **摸学员水平**：依据输入的学员背景判断现有水平与缺口，缺口处标（待确认），不替学员脑补；
3. **排大纲**：按最近发展区把内容切成模块——已会的一笔带过，缺口处重点讲；每个模块配教学动作和时长；
4. **设计练习**：提取练习 / 间隔重复 / 交错练习三类各落一道具体的题或一张具体的表，不许写"加强练习"这类空话；
5. **配评估与巩固**：给每个目标配一个检验方法，再给一张课后复习日程和常见错误清单。

## 质量规则（必须遵守）

- **目标必须可检验**：教学目标用行为动词（说出、操作、判断、区分、完成……），禁止"了解""熟悉""掌握"这类不可检验的词单独出现；
- **练习必须落地**：提取练习要写出具体回忆题（至少 3 道），间隔重复要写出具体复习时间表（第几天复习什么），交错练习要写出混合题型示例——不允许"多做练习""加强记忆"这类空话；
- **学员信息不足标（待确认）**：学员背景没给清楚的地方，如实标注，不编造学员水平；
- **时长自洽**：课程大纲里各模块时长之和必须等于总时长（`--duration` 传入的分钟数；未传则给出一个建议总时长并保证内部自洽）；
- **难度贴着最近发展区**：不讲学员已经会的东西凑时长，也不直接跳到远超水平的内容；
- **反馈要快**：每个练习都要写清楚怎么给学员反馈（对答案、看演示、讲师巡场点评）。

## 边界与异常处理

- 主题偏理论、几乎无技能练习（如"公司发展史"）→ 交错练习可弱化，但提取练习与间隔重复仍必须保留；
- 学员背景完全空白 → 学员画像一节全标（待确认），并在开头提示主讲人"开课前务必先做 5 分钟前置摸底"；
- 时长很短（≤30 分钟）→ 压缩模块数，练习只保留课中提取练习，课后间隔重复表照常给；
- 合规 / 红线类培训 → 评估方式必须含"红线题答错即不通过"的一票否决项；
- 多人大班 vs 一对一带教 → 练习设计注明可分组 / 可一对一开展的形式。

## 与脚本配合

- 批量 / 命令行场景：`scripts/draft_teach.py`（纯标准库，一条命令跑通）；输入为培训主题 + 学员背景（+ 可选时长 / 人数 / 目标）的文本，输出为成稿教案 Markdown；`--duration` 传入总时长（分钟），注入系统提示词控制课程大纲的时长分配。
- 自定义模板：复制 `scripts/templates/teach.template.md` 修改后使用。
