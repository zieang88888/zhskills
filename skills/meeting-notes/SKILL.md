# 会议纪要（meeting-notes）

## 这个技能做什么

把一段可能杂乱、重复、口语化的会议 / 访谈 / 播客转写稿，整理成一份**结构完整、可以直接交付**的 Markdown 会议纪要草稿。

## 输入要求

- 转写稿文本：直接粘贴，或 .txt / .md 文件路径（配合脚本批量处理）。
- 带时间戳最好（`00:12` 或 `[00:12:34]` 均可）；没有时间戳也可以，用「要点 1 / 要点 2」编号代替。
- 可选补充：会议议题、参会人名单、会议背景——有则更准确，无则从文中推断并标注"（推断）"。

## 输出结构（严格按此模板）

1. **标题与会议信息**：议题 / 参会人 / 时间 / 形式，缺失项留空并标注。
2. **一句话摘要**：用 1–2 句话概括会议核心结论。
3. **讨论要点**：按主题分组，尽量带时间戳，不按时间流水账。
4. **决议**：完成项用 `[x]`，未完成项用 `[ ]`。
5. **行动项**：表格（事项 / 负责人 / 截止）；无负责人或截止时标注"（待确认）"。
6. **待确认事项**：遗留问题、悬而未决的点。
7. **风险提示**：依赖关系、预算、时间风险等，仅基于原文内容。

## 工作流程

1. **通读全文**：先识别有几个主题、谁在推进什么、结论是什么。
2. **逐主题提炼**：每个主题给出一句话要点 + 关键细节 + 时间戳。
3. **提取决议与行动项**：以"定 / 拍板 / 就按…来 / 负责… / 截止…"等信号为准。
4. **按模板组装**：输出完整 Markdown。
5. **对照原文复核**：有没有漏掉的数字、金额、日期、人名、项目名？有没有编造？

## 质量规则（必须遵守）

- **忠于原文**：只整理转写稿中真实出现的信息；原文没有的，一律不补写、不猜测。
- **信息保全**：数字、金额、日期、人名、项目名一个都不能丢。
- **不确定就标注**：听不清 / 有歧义 / 信息不足处，写"（待确认）"，不替用户做主。
- **保持中性**：只记录事实，不评价参会者个人。
- **长文组织**：超过 30 分钟的长会议按主题分组输出，禁止流水账式罗列。
- **术语一致**：同一项目 / 专有名词全文统一写法，首次出现可括注上下文。

## 边界与异常处理

- 无时间戳 → 用「要点 1 / 要点 2」编号代替。
- 多人混声、噪音、听不清 → 仅保留可辨识内容，并注明"该段转写质量较低"。
- 中英混杂 → 保留原文关键术语，不强行翻译。
- 原文过短或信息不足 → 如实整理，并说明"信息有限，建议补充"。
- 口语、重复、跑题 → 去重、去口水话，但保留观点本身。

## 与脚本配合

- 批量 / 命令行场景：`scripts/draft_meeting_notes.py`（纯标准库，一条命令跑通）。
- 自定义模板：复制 `scripts/templates/meeting-notes.template.md` 修改后使用。
