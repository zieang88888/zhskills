# 文档摘要 · doc-summary

## 这个技能做什么

把一份可能几十页的长文档（报告、方案、制度、论文、合同条款说明、会议材料等），浓缩成**决策者视角的一页摘要**：先给一句话结论，再列关键发现（数字 / 事实 / 结论）、影响与风险、建议行动、待确认事项。让不看原文的人也能快速拍板或追问。

## 输入要求

- 文档文本（必填）：直接粘贴，或 .txt / .md 文件路径，或 `-` 从标准输入读取；长文本自动分块。
- 可选补充：
  - 摘要用途：向上汇报 / 快速决策 / 存档；
  - 读者背景：读者是谁、关心什么；
  - 特别关注点：如预算、合规、时间线等。

## 输出结构（模板见 scripts/templates/doc-summary.template.md）

1. **文档标题与信息来源**：文档名 / 出处，缺失项标注（待确认）。
2. **一句话结论**：一句话说清这份文档最核心的结论。
3. **关键发现**：每条带原文位置或页码 / 章节标注；按重要性排序，不按章节顺序罗列。
4. **影响与风险**：对业务 / 项目 / 决策的影响，仅基于原文。
5. **建议行动**：下一步建议，区分原文明确提出的与基于发现推导的。
6. **待确认事项**：原文没讲清、口径不明、自相矛盾的地方。

## 工作流程

1. **第一遍（逐段抽取）**：长文档按约 9000 字分块，每段先抽取「关键发现条目」——数字、金额、日期、人名、机构名、项目名、明确结论、重要事实，逐条记录并标注其在原文的位置。
2. **第二遍（汇总成稿）**：把全部抽取结果汇总成一张一页摘要（第二次模型调用），按重要性组织，面向决策者成稿。
3. **短文档**：单段输入只跑一遍，直接生成最终摘要。
4. **对照复核**：数字、金额、日期、人名、项目名有没有漏？有没有编造？矛盾点有没有指出？

## 质量规则（必须遵守）

- **忠于原文**：只总结文档里真实出现的信息，绝不脑补、不替原文下结论。
- **信息保全**：数字、金额、日期、人名、项目名一个不丢。
- **不确定就标注**：原文没讲清 / 有歧义处写「（待确认）」。
- **结论先行**：面向决策者——第一句就是结论，按重要性排序，不按章节流水罗列。
- **指出矛盾**：原文自相矛盾或前后口径变化时必须点出。
- **控制篇幅**：一页以内（约 800–1200 字）。

## 边界与异常处理

- 原文没有页码 / 章节 → 用「第 N 段」或就近标题标注位置。
- 文档过短 / 信息不足 → 如实摘要，并说明「信息有限」。
- 中英混杂 → 保留关键术语原文，不强行翻译。
- 原文自相矛盾 → 在「待确认事项」中并列呈现两种口径。

## 与脚本配合

- 批量 / 命令行场景：`scripts/draft_doc_summary.py`（纯标准库，一条命令跑通；长文自动两遍式）。
- 自定义模板：复制 `scripts/templates/doc-summary.template.md` 修改后使用。
