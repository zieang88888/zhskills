## 本改编做了什么

1. 保留原技能的核心方法论：证据先于文字（动笔前先建证据表）、论证先于章节（先画"背景→问题→目标→方案→预期价值"论证图）、契约先于段落（每节写死 purpose / allowed claims / forbidden claims）、内容先于语言（先查科学逻辑再做语言打磨）、不自动升级事实强度、删除胜于解释、该停就停；以及四层 QA（内容层 → 结构层/格式层 → 语言层 → 评分阈值层）的质量保障流水线。
2. 去掉原技能对 `references/` 文献目录与多文件项目结构（00_scope / research_canon / state.json / sources / drafts / qa_logs）的强依赖，改为用户在输入中直接提供「立项主题 + 事实/数据/需求清单」，证据表由用户清单自动登记，不再要求文献检索目录。
3. 把科研写作场景平移到中文项目申报 / 立项报告场景：输出七节结构（基本信息 / 背景与意义 / 问题与目标 / 方案与计划 / 预期价值与风险 / 证据表 / 四层QA自检报告），问题与目标一一对应、目标可检验。
4. 按 zhskills 标准重写 SKILL.md 结构（定位 / 输入要求 / 输出结构 / 工作流程 / 质量规则 / 边界与异常处理）。
5. 新增可执行 CLI（scripts/draft_proposal_writer.py）：零依赖、OpenAI 兼容接口、命令行调用，将"提示词技能"升级为"可运行流水线"。
6. 新增输出模板（scripts/templates/proposal-writer.template.md）。
